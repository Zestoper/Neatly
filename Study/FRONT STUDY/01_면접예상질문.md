# 프론트엔드 면접 예상 질문

---

## React 기본

**Q. useState와 useEffect의 역할을 설명해주세요.**

`useState`는 컴포넌트가 기억해야 하는 값(상태)을 선언합니다. 상태가 바뀌면 컴포넌트가 리렌더링됩니다.

`useEffect`는 렌더링 후 실행할 부수 효과(API 호출, 구독, 타이머 등)를 선언합니다. 의존성 배열로 언제 실행할지 제어합니다.

```typescript
// Dashboard.tsx 예시
useEffect(() => {
    getSyncStatus().then(data => setSyncStatus(data)).catch(() => {});
}, [isPremium]);  // isPremium이 바뀔 때마다 실행
```

---

**Q. useEffect 의존성 배열의 역할이 뭔가요?**

- `[]` (빈 배열): 마운트 시 한 번만 실행
- `[value]`: value가 바뀔 때마다 실행
- 생략: 렌더링마다 실행 (거의 쓰지 않음)

의존성 배열에 없는 값을 내부에서 참조하면 오래된 값을 보는 클로저 버그가 생깁니다.

---

**Q. React에서 리렌더링은 언제 일어나나요?**

1. `setState` 호출
2. 부모 컴포넌트가 리렌더링될 때 (props가 바뀌지 않아도)
3. Context 값이 바뀔 때

Neatly에서는 `ToastContext`가 바뀌면 Toast를 사용하는 모든 컴포넌트가 리렌더링됩니다.

---

**Q. Context API가 뭔가요? Neatly에서 어떻게 썼나요?**

깊이 중첩된 컴포넌트에 props를 일일이 내려주지 않고 전역으로 값을 공유하는 방법입니다.

Neatly에서는 `ToastContext`로 어떤 페이지에서든 `showToast("메시지")`를 호출할 수 있게 했습니다. `App.tsx`에서 `<ToastProvider>`로 전체 앱을 감쌌습니다.

## TypeScript

**Q. TypeScript를 왜 쓰나요?**

런타임이 아닌 컴파일 타임에 타입 오류를 잡을 수 있습니다. API 응답 타입을 정의해두면 오타, 잘못된 필드 접근을 IDE에서 바로 발견할 수 있습니다.

```typescript
// Neatly Dashboard.tsx 예시
type Document = {
    id: string;
    title: string;
    created_at: string;
    tags: Tag[];
};
const [documents, setDocuments] = useState<Document[]>([]);
```

---

**Q. 제네릭이 뭔가요?**

타입을 파라미터처럼 받는 문법입니다. 다양한 타입에 동일한 로직을 적용할 때 씁니다.

```typescript
useState<Document[]>([])     // T = Document[]
useState<string | null>(null) // T = string | null
```

## Axios / API

**Q. Axios 인터셉터가 뭔가요? Neatly에서 어떻게 썼나요?**

요청/응답이 나가거나 들어오기 전에 공통 처리를 삽입하는 미들웨어입니다.

Neatly의 `client.ts`에서:
- **요청 인터셉터**: `localStorage`에서 JWT를 꺼내 모든 요청 헤더에 자동으로 `Authorization: Bearer <token>`을 추가합니다.
- **응답 인터셉터**: 401 응답이 오면 토큰을 삭제하고 로그인 페이지로 리다이렉트합니다.

이 덕분에 개별 API 함수에서 헤더나 인증 처리를 반복할 필요가 없습니다.

---

**Q. Render 백엔드가 sleep 상태일 때 어떻게 처리하나요?**

`client.ts`에서 `timeout: 90000` (90초)으로 설정했습니다. Render 무료 플랜의 콜드 스타트가 최대 약 60초 걸리기 때문입니다. 로그인/회원가입 페이지 진입 시 `warmUpServer()`로 백엔드를 미리 깨웁니다.

## SPA 라우팅

**Q. SPA에서 새로고침하면 404가 나는 이유가 뭔가요? Neatly는 어떻게 해결했나요?**

SPA는 `index.html` 하나로 모든 라우팅을 JavaScript로 처리합니다. `example.com/documents`로 직접 접속하면 서버가 `/documents` 경로의 파일을 찾다가 없어서 404를 반환합니다.

`vercel.json`에 모든 경로를 `index.html`로 rewrite하는 설정을 추가해 해결했습니다.

---

**Q. React Router의 useNavigate와 Link의 차이가 뭔가요?**

`Link` : JSX에서 클릭 가능한 링크를 렌더링합니다. 브라우저 기본 탐색 대신 클라이언트 사이드 라우팅을 씁니다.

`useNavigate` : 코드에서 프로그래밍적으로 이동할 때 씁니다. 예: 로그인 성공 후 대시보드로 이동, 인증 실패 시 로그인 페이지로 리다이렉트.

## 상태 관리

**Q. localStorage vs useState — 언제 어떤 걸 쓰나요?**

`useState` : 렌더링에 영향을 주는 일시적인 데이터 (로딩 여부, 모달 열림 상태, 폼 입력값).

`localStorage` : 새로고침 후에도 유지해야 하는 데이터 (JWT, plan, userName).

단, localStorage 변경은 React 상태가 아니므로 컴포넌트가 자동으로 리렌더링되지 않습니다. Neatly에서 `plan`을 localStorage에 저장하는데, 컴포넌트 초기 렌더링 시에만 읽어 `isPremium`을 계산합니다.

---

**Q. plan을 localStorage에서 읽는 방식의 문제점은 뭔가요?**

```typescript
const plan = localStorage.getItem("plan") ?? "FREE";
const isPremium = plan === "PREMIUM";
```

DB의 실제 플랜과 localStorage 값이 불일치할 수 있습니다. 예를 들어 플랜이 다운그레이드됐는데 localStorage가 업데이트되지 않으면 UI에서는 Premium 기능이 보입니다. 실제 API 호출 시 403이 반환되므로 기능은 막히지만 UI가 부정확하게 표시됩니다.

`Layout.tsx`에서 마운트 시 `/auth/me`를 호출해 plan을 갱신하므로 보통은 일치하지만, 갱신 전 첫 렌더링에서는 stale 값을 씁니다.

## 브라우저 API

**Q. iOS Safari에서 Notification API 오류가 생긴 이유와 해결 방법은요?**

iOS Safari는 Web Notifications API를 지원하지 않아 `window.Notification`이 `undefined`입니다. 이 상태에서 `Notification.requestPermission()`을 호출하면 런타임 오류가 나고 ErrorBoundary가 없으면 앱 전체가 흰 화면이 됩니다.

해결:
1. `typeof Notification !== 'undefined'` 가드로 접근 전 지원 여부 확인
2. 최상단 `ErrorBoundary`로 치명적 렌더 오류를 catch해 사용자에게 오류 메시지 표시
3. 알림 불가 환경에서는 인앱 토스트로 폴백
