## client.ts — Axios 인스턴스와 인터셉터

```typescript
export const api = axios.create({
    baseURL: import.meta.env.VITE_API_BASE_URL ?? "http://localhost:8000",
    timeout: 90000,  // Render 콜드 스타트 대응
});

// 요청 인터셉터 — 모든 요청에 JWT 자동 첨부
api.interceptors.request.use((config) => {
    const token = localStorage.getItem("token");
    if (token) {
        config.headers.Authorization = `Bearer ${token}`;
    }
    return config;
});

// 응답 인터셉터 — 401이면 토큰 삭제 후 로그인 페이지로
let redirecting = false;  // 중복 리다이렉트 방지 플래그
api.interceptors.response.use(
    (response) => response,
    (error) => {
        if (error.response?.status === 401 && !redirecting) {
            redirecting = true;
            localStorage.removeItem("token");
            window.location.href = "/login";
        }
        return Promise.reject(error);
    }
);
```

- `redirecting` 플래그 : 여러 API가 동시에 401을 받으면 여러 번 리다이렉트가 일어날 수 있습니다. 첫 번째 401에서만 처리합니다.
- `Promise.reject(error)` : 401 외의 오류는 그대로 던져 각 페이지의 catch 블록에서 처리합니다.
- `import.meta.env.VITE_API_BASE_URL` : Vite 환경 변수. `.env` 파일의 `VITE_` 접두사 변수를 읽습니다.

## ToastContext.tsx — 전역 토스트 알림

```typescript
const ToastContext = createContext<ToastContextValue>({
    showToast: () => {},         // 기본값 — Provider 밖에서 쓰면 noop
    showCalendarAlert: () => {},
});

export function ToastProvider({ children }) {
    const [toasts, setToasts] = useState<ToastItem[]>([]);

    const showToast = useCallback((message: string, type: ToastType = "success") => {
        const id = Date.now();
        setToasts(prev => [...prev, { id, message, type }]);
        setTimeout(() => {
            setToasts(prev => prev.filter(t => t.id !== id));
        }, 3000);  // 3초 후 자동 제거
    }, []);

    return (
        <ToastContext.Provider value={{ showToast, showCalendarAlert }}>
            {children}
            {/* 토스트 렌더링 */}
        </ToastContext.Provider>
    );
}

export function useToast() {
    return useContext(ToastContext);
}
```

- `useCallback` : 컴포넌트가 리렌더링돼도 `showToast` 함수 참조가 바뀌지 않습니다. Context value가 불필요하게 바뀌는 것을 방지합니다.
- `Date.now()` : 토스트 ID로 씁니다. 같은 메시지가 여러 번 떠도 각각 독립적으로 사라집니다.
- `prev => prev.filter(t => t.id !== id)` : 상태 업데이트 함수 형태를 씁니다. 최신 상태를 항상 보장합니다.

## Dashboard.tsx — 여러 useEffect 패턴

```typescript
// 1. 마운트 시 한 번만 실행
useEffect(() => {
    const init = async () => {
        const [docsData, meData] = await Promise.all([
            getDocuments(),
            api.get("/auth/me"),
        ]);
        setDocuments(docsData);
        setGmailConnected(!!meData.data.gmail_access_token);
    };
    init();
}, []);

// 2. isPremium이 바뀔 때마다 실행
useEffect(() => {
    if (!isPremium) return;
    getSyncStatus().then(data => setSyncStatus(data)).catch(() => {});
}, [isPremium]);
```

- `Promise.all([...])` : 여러 API를 병렬로 호출합니다. 순차 호출보다 빠릅니다.
- `!!meData.data.gmail_access_token` : `!!`로 truthy 값을 boolean으로 변환합니다.
- `async` 함수를 useEffect 안에 중첩해서 쓰는 이유: useEffect 콜백은 async를 직접 쓸 수 없습니다 (Promise를 반환하면 안 됨). 내부에서 async 함수를 선언하고 호출합니다.

## handleGmailSync — 버튼 핸들러 패턴

```typescript
const handleGmailSync = async () => {
    setSyncingGmail(true);  // 버튼 비활성화
    try {
        const res = await syncEmails();
        setSyncStatus(prev => ({ ...prev!, last_sync: res.last_sync ?? null }));
        if (res.synced > 0) {
            const docsData = await getDocuments();
            setDocuments(docsData);
            showToast(`새 이메일 ${res.synced}개 동기화됐습니다.`);
        } else {
            showToast("새 이메일이 없습니다.");
        }
    } catch {
        showToast("Gmail 동기화에 실패했습니다.");
    } finally {
        setSyncingGmail(false);  // 항상 버튼 재활성화
    }
};
```

- `finally` : 성공/실패에 관계없이 로딩 상태를 항상 초기화합니다. 없으면 오류 시 버튼이 영구히 비활성화됩니다.
- `prev!` : TypeScript에서 `prev`가 null일 수 있으므로 `!`로 non-null을 단언합니다.

## useCalendarNotifications.ts — 커스텀 훅

커스텀 훅은 `use`로 시작하는 함수로, React 훅(useState, useEffect 등)을 포함하는 로직을 컴포넌트에서 분리합니다.

```typescript
export function useCalendarNotifications() {
    const { showCalendarAlert } = useToast();

    useEffect(() => {
        // 일정 목록 조회 후 알림 타이머 등록
        getTodayEvents().then(events => {
            events.forEach(event => {
                const now = Date.now();
                const eventTime = new Date(event.event_date).getTime();
                const tenMinBefore = eventTime - 10 * 60 * 1000;

                if (tenMinBefore > now) {
                    setTimeout(() => {
                        // 알림 권한 확인 후 발동
                        if (typeof Notification !== "undefined" && Notification.permission === "granted") {
                            new Notification(event.title);
                        } else {
                            showCalendarAlert("일정 알림", event.title);  // 인앱 폴백
                        }
                    }, tenMinBefore - now);
                }
            });
        });
    }, []);
}
```

- `Layout.tsx`에서 `useCalendarNotifications()`를 호출해 로그인된 모든 페이지에서 알림이 작동합니다.
- 커스텀 훅의 장점: 동일한 로직을 여러 컴포넌트에서 재사용할 수 있고, 컴포넌트 코드가 간결해집니다.

## ErrorBoundary — 클래스 컴포넌트

```typescript
class ErrorBoundary extends React.Component<...> {
    state = { hasError: false };

    static getDerivedStateFromError() {
        return { hasError: true };  // 에러 발생 시 상태 변경
    }

    componentDidCatch(error: Error) {
        console.error("ErrorBoundary caught:", error);
    }

    render() {
        if (this.state.hasError) {
            return <div>오류가 발생했습니다.</div>;
        }
        return this.props.children;
    }
}
```

- React 함수형 컴포넌트로는 구현할 수 없습니다. `getDerivedStateFromError`와 `componentDidCatch`는 클래스 컴포넌트 생명주기 메서드이기 때문입니다.
- `this.props.children`에서 렌더링 오류가 발생하면 fallback UI를 보여줍니다. iOS Safari Notification 오류처럼 예상치 못한 런타임 오류를 앱 크래시 없이 처리합니다.
