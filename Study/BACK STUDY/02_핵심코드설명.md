## auth.py — JWT 발급과 검증

```python
def create_access_token(data: dict):
    to_encode = data.copy()
    expire = datetime.now(timezone.utc) + timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES)
    to_encode.update({"exp": expire})
    return jwt.encode(to_encode, SECRET_KEY, algorithm=ALGORITHM)
```

- `data.copy()` : 원본 dict를 변경하지 않으려고 복사합니다.
- `"exp"` : JWT 표준 클레임. 만료 시간을 담는 키입니다. `python-jose`가 자동으로 검증합니다.
- `HS256` : 대칭 키 알고리즘. 서버만 SECRET_KEY를 알기 때문에 토큰 변조를 감지할 수 있습니다.

```python
def get_current_user(token: str = Depends(oauth2_scheme), db: Session = Depends(get_db)):
```

- `oauth2_scheme` : `Authorization: Bearer <token>` 헤더에서 토큰 부분만 자동 추출합니다.
- `JWTError` : 만료, 서명 불일치, 형식 오류 등 모든 JWT 예외를 포함합니다.
- `"sub"` : subject(주체). 로그인 시 사용자 ID를 여기에 담았습니다.

## database.py / get_db() — DB 세션 관리

```python
def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

- `yield` : 요청 처리 중에는 세션을 열어두고, 요청이 끝나면(정상/예외 모두) `finally`에서 반드시 닫습니다.
- FastAPI의 `Depends(get_db)`에 연결해 모든 라우터에서 동일한 패턴으로 세션을 주입받습니다.

## documents.py — N+1 쿼리 최적화

```python
# 나쁜 방식 (N+1) — 문서마다 태그 쿼리 1회씩 실행
def doc_with_tags(doc, db):
    tags = db.query(Tag).join(DocumentTag, ...).filter(DocumentTag.document_id == doc.id).all()
    ...

# 좋은 방식 — 전체 태그를 IN 쿼리 1회로 조회
def docs_with_tags_batch(docs: list, db) -> list:
    doc_ids = [str(d.id) for d in docs]
    rows = db.query(DocumentTag, Tag).join(Tag, ...).filter(
        DocumentTag.document_id.in_(doc_ids)  # IN 쿼리
    ).all()
    tags_map: dict = {did: [] for did in doc_ids}
    for dt, tag in rows:
        tags_map[str(dt.document_id)].append({"id": str(tag.id), "name": tag.name})
    return [_doc_to_dict(doc, tags_map[str(doc.id)]) for doc in docs]
```

- `.in_(doc_ids)` : WHERE document_id IN (...) 쿼리 한 번으로 전체 태그를 가져옵니다.
- 이후 Python dict로 `{document_id: [tags]}` 매핑해서 각 문서에 붙입니다.
- 문서 100개 기준 쿼리 101회 → 2회로 감소합니다.

## gmail_utils.py — OAuth 토큰 자동 갱신

```python
def refresh_if_expired(creds: Credentials, user, db: Session):
    if (creds.expiry is None or creds.expired) and creds.refresh_token:
        creds.refresh(GoogleRequest())
        user.gmail_access_token = creds.token
        if creds.expiry:
            user.gmail_token_expiry = creds.expiry
        db.commit()
```

- `creds.expiry is None` : OAuth 콜백에서 만료 시각을 저장하지 않은 기존 유저 안전망입니다.
- `creds.expired` : `google-auth` 라이브러리가 내부적으로 `expiry < utcnow()` 비교합니다.
- `creds.refresh(GoogleRequest())` : refresh_token으로 Google에 새 access_token을 요청합니다.
- 갱신 후 즉시 DB에 저장해 다음 요청에서도 유효한 토큰을 씁니다.

**주의**: 초기 구현에서 OAuth 콜백(`gmail_callback`)에 `expires_at` 저장이 누락되어 `creds.expiry`가 항상 None이었습니다. 이로 인해 `creds.expired`가 항상 False → 갱신 건너뜀 → 1시간 후 Gmail API 401 → `except` 절이 0 반환 → 프론트엔드가 "새 이메일 없음"으로 오인하는 silent 실패가 있었습니다.

## chat.py — ConnectionManager와 WebSocket 엔드포인트

```python
class ConnectionManager:
    def __init__(self):
        self.rooms: dict[str, list[tuple[WebSocket, str, str]]] = {}

    async def connect(self, room_id, ws, user_id, user_name):
        await ws.accept()
        room = self.rooms.setdefault(room_id, [])
        # 같은 user_id 기존 연결 교체 (재연결 중복 방지)
        for old_ws, uid, _ in [item for item in room if item[1] == user_id]:
            try:
                await old_ws.close()
            except Exception:
                pass
        self.rooms[room_id] = [item for item in room if item[1] != user_id]
        self.rooms[room_id].append((ws, user_id, user_name))

    async def broadcast(self, room_id, message):
        for ws, _, _ in self.rooms.get(room_id, []):
            await ws.send_json(message)
```

- `dict[str, list[tuple[...]]]` : 방 ID → 연결 목록 딕셔너리입니다.
- `setdefault(room_id, [])` : 키가 없으면 빈 리스트를 생성하고 반환합니다.
- 재연결 시 기존 연결을 먼저 닫고 새 연결로 교체합니다. 이 로직 없이는 재연결 시 같은 유저의 연결이 2개가 되어 메시지가 중복 수신됩니다.
- WebSocket 엔드포인트는 HTTP 의존성(`Depends(get_db)`)이 동작하지 않아 `SessionLocal()`을 직접 생성합니다.

## scheduler.py — APScheduler 구조

```python
def start_scheduler():
    if scheduler.running:
        return  # 중복 등록 방지

    scheduler.add_job(sync_all_premium_emails,
                      trigger=IntervalTrigger(minutes=2), id="email_sync")
    scheduler.add_job(generate_daily_briefings,
                      trigger=CronTrigger(hour=8, minute=0), id="daily_briefing")
    scheduler.add_job(cleanup_old_trash,
                      trigger=CronTrigger(hour=3, minute=0), id="trash_cleanup")
    scheduler.start()
```

- `BackgroundScheduler` : FastAPI 메인 스레드와 별도 스레드에서 실행됩니다.
- `replace_existing=True` : 같은 `id`의 작업이 이미 등록되어 있으면 교체합니다.
- 각 작업에서 `SessionLocal()`을 독립적으로 열고 `finally`에서 닫습니다. 스케줄러 스레드는 FastAPI 요청 사이클 밖이라 공유 세션을 사용할 수 없기 때문입니다.
