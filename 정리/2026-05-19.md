### 1. Gmail 자동 분류 (AI)

**관련 파일:** `backend/routers/email_sync.py`

Gmail 자동 동기화 시 Groq LLM이 이메일 내용을 분석해 폴더와 태그를 자동으로 지정.

#### 동작 흐름

```
sync_user_emails() 실행
  └── 사용자의 email 타입 폴더 + 태그 목록 조회 (루프 전에 한 번)
  └── 새 이메일마다 _classify_email_doc() 호출
        └── Groq llama-3.3-70b-versatile에 JSON 응답 요청
            {"folder": "폴더명 or null", "tags": ["태그명", ...]}
        └── 이름 → ID 매핑
  └── Document 생성 후 db.flush()로 ID 확정
  └── DocumentTag 행 삽입
```

#### 핵심 코드 포인트

- `db.flush()`: 커밋 없이 DB에 반영해 `new_doc.id`를 얻음 → `DocumentTag` 생성 가능
- 폴더/태그 목록을 루프 밖에서 한 번만 조회해 불필요한 쿼리 방지
- Groq 응답 파싱 실패 시 `(None, [])` 반환 — 분류 실패해도 동기화는 계속 진행

### 8. 삭제 흐름 정리

| 위치 | 삭제 동작 |
|---|---|
| Documents 목록 | 휴지통으로 이동 (soft delete) |
| Documents 폴더 필터 뷰 | 폴더에서만 제거 (`folder_id = null`) |
| DocumentDetail | 폴더에서 열었으면 폴더 제거, 아니면 휴지통 |
| Emails (Gmail 목록) | Gmail 휴지통 이동 + Neatly 휴지통에 기록 |
| Emails 폴더 뷰 | 폴더에서만 제거 |
| EmailDetail | Gmail 휴지통 이동 + Neatly 휴지통에 기록 |
| Trash | 복원 또는 영구 삭제 |

#### 버그 수정 — 휴지통 라우터 순서

`GET /documents/trash`가 `GET /documents/{document_id}` 뒤에 등록되어
FastAPI가 "trash"를 document_id로 해석 → 404 반환.

**수정:** `/documents/trash` 라우터를 `/documents/{document_id}` **앞**으로 이동.

### 9. 전역 실시간 반영 (RefreshContext)

**관련 파일:** `my-app/src/context/RefreshContext.tsx`

`RefreshProvider`가 `refreshKey` 카운터를 제공. 어떤 페이지에서든 데이터 변경 후 `bump()`를 호출하면 `refreshKey`가 증가하고, 이를 의존성 배열에 포함한 모든 useEffect가 즉시 재실행됨.

#### 연결된 페이지

- `Documents.tsx` — 문서 목록 재조회
- `Trash.tsx` — 휴지통 목록 재조회
- `Emails.tsx` — 폴더 문서 목록 재조회
- `Sidebar.tsx` — 폴더 목록 재조회

#### bump() 호출 위치

Documents 삭제/업로드, DocumentDetail 삭제/저장, EmailDetail 삭제, Emails 삭제, Trash 복원/영구삭제, Sidebar 폴더 추가/수정/삭제
