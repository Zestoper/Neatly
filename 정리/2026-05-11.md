### 3. Gmail 연동

**관련 파일:** `backend/routers/gmail.py` (신규), `backend/models.py`, `my-app/src/pages/Emails.tsx` (신규)

#### 3-1. DB 변경 (models.py)
User 테이블에 Gmail 토큰 컬럼 3개 추가:
- `gmail_access_token` (Text) — Gmail API 호출용 단기 토큰
- `gmail_refresh_token` (Text) — 만료 시 재발급용 장기 토큰
- `gmail_token_expiry` (DateTime) — access_token 만료 시각

Document 테이블에 추가:
- `raw_html` (Text, nullable) — 이메일 원본 HTML 저장용

#### 3-2. OAuth 흐름 (gmail.py)
- `requests_oauthlib.OAuth2Session` 사용 (google-auth-oauthlib.Flow는 PKCE 자동 추가로 콜백 실패)
- `GET /auth/gmail` → Google OAuth 인증 URL 생성 → 프론트가 redirect
- `GET /auth/gmail/callback` → 인증 코드 교환 → 토큰 저장 → 프론트로 `?connected=true` 리다이렉트

#### 3-3. 이메일 목록 / 변환
- `GET /emails` → Gmail API로 최근 20개 메일 제목·발신자 반환
- `POST /emails/{message_id}/to-document` → 메일 본문 파싱 → 문서 생성 (AI 요약 포함)

#### 3-4. 본문 파싱 파이프라인

```
Gmail API 응답 (base64url)
  └── base64 디코드
  └── charset 감지 (Content-Type 헤더 → 없으면 UTF-8 → 실패 시 EUC-KR)
  └── text/plain 우선 / 없으면 text/html → 태그 제거
  └── _clean_body() : 공백·CSS·URL·ASCII아트·빈 괄호 제거
  └── raw_text로 저장 + raw_html(원본 HTML)도 별도 저장
```

#### 3-5. 이메일 렌더링 (DocumentDetail.tsx)
- `raw_html`이 있으면 `<iframe srcDoc={doc.raw_html} sandbox="allow-same-origin" />` 으로 원본 렌더링
- 부모 페이지 CSS와 완전히 격리됨 (sandbox)
- `raw_text`는 iframe 아래에 항상 표시

#### 3-6. Emails 페이지 (Emails.tsx)
- PREMIUM 플랜이 아니면 업그레이드 유도 화면
- Gmail 미연결이면 연결 버튼 표시
- 이메일 목록에서 "문서로 변환" 버튼 → 변환 중 / 변환 완료 상태 관리
- `converted` 상태를 `Set<string>`으로 관리 — 변환 완료된 이메일 ID 추적

### 4. 태그 기능

**관련 파일:** `backend/models.py`, `backend/routers/tags.py` (신규), `backend/routers/documents.py`, `backend/main.py`, `my-app/src/api/tags.ts` (신규), `my-app/src/pages/DocumentDetail.tsx`, `DocumentDetail.module.css`

#### 4-1. DB 모델 (models.py)
N:M 관계를 위한 테이블 2개 추가:

```
Tag
  id (UUID, PK)
  user_id (FK → User)
  name (String 50)
  created_at

DocumentTag  ← 중간 테이블
  document_id (FK → Document, PK)
  tag_id (FK → Tag, PK)
  복합 기본키 → (document_id, tag_id) 쌍이 유일
```

#### 4-2. 태그 API (routers/tags.py)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | /tags | 내 태그 목록 반환 |
| POST | /tags | 태그 생성 (중복 이름이면 기존 반환) |
| DELETE | /tags/{tag_id} | 태그 삭제 |
| POST | /documents/{id}/tags | 문서에 태그 추가 (없으면 자동 생성, `db.flush()` 로 ID 확정 후 연결) |
| DELETE | /documents/{id}/tags/{tag_id} | 문서에서 태그 제거 (태그 자체는 유지) |

#### 4-3. 문서 응답에 태그 포함 (routers/documents.py)
- `get_tags_for_doc(doc_id, db)`: JOIN 쿼리로 문서에 달린 태그 목록 조회
- `doc_with_tags(doc, db)`: 문서 ORM 객체 → dict 변환 + tags 필드 추가
- 모든 문서 엔드포인트(목록, 단건, 수정, 생성)에 적용

#### 4-4. 프론트엔드 (DocumentDetail.tsx)

**읽기 모드:** 제목 아래에 태그 배지 목록 표시 (X 버튼 없음)

**수정 모드:** 태그 에디터 표시
- 현재 태그 배지 목록 + X 버튼으로 제거
- 입력창에 태그 이름 입력 후 Enter → 서버에서 태그 찾거나 생성 → 상태 업데이트
- 중복 추가 방지: `prev.find(t => t.id === newTag.id)`

**CSS 추가 클래스:**

| 클래스 | 설명 |
|---|---|
| `.tagReadList` | 읽기 모드 태그 가로 나열 컨테이너 |
| `.tagEditor` | 수정 모드 전체 컨테이너 |
| `.tagList` | 수정 모드 배지 나열 행 |
