# 무료 배포 가이드 — Supabase + Render + Vercel

React + FastAPI 앱을 완전 무료로 배포하는 방법을 단계별로 정리한다.

---

## 전체 구조

```
사용자 브라우저
    ↕  HTTPS
Vercel (React 프론트엔드)
    ↕  HTTPS API 호출
Render (FastAPI 백엔드)
    ↕  PostgreSQL 연결
Supabase (DB)
```

| 역할 | 서비스 | 무료 제한 |
|------|--------|-----------|
| DB | Supabase | 500MB, 2개 프로젝트 |
| 백엔드 | Render | 15분 비활성 시 sleep, 월 750시간 |
| 프론트엔드 | Vercel | 무제한 (개인 프로젝트 기준) |

---

## 1단계 — Supabase (PostgreSQL)

### 1-1. 프로젝트 생성
1. [supabase.com](https://supabase.com) 접속 → GitHub 로그인
2. New project → 이름 입력, 비밀번호 설정 (특수문자 X 권장), 리전 선택
3. 프로젝트 생성까지 1~2분 대기

### 1-2. 연결 URL 확인
- 좌측 메뉴 Connect 클릭
- **Session pooler** 탭 선택 (Transaction pooler X)
- 연결 문자열 복사:
  ```
  postgresql://postgres.프로젝트ID:비밀번호@aws-1-ap-northeast-2.pooler.supabase.com:5432/postgres
  ```

> **왜 Session pooler를 써야 하나?**
> Render 무료 티어는 IPv6를 지원하지 않는다.
> Supabase 직접 연결(db.xxx.supabase.co)은 IPv6 전용이라 Render에서 연결이 안 된다.
> Session pooler는 IPv4로 연결되므로 Render에서도 정상 작동한다.

### 1-3. DB 테이블 생성
백엔드 로컬에서 실행:
```bash
cd backend
# .env에 Supabase 연결 URL 입력 후
python3 create_tables.py
```

## 2단계 — Render (FastAPI 백엔드)

### 2-1. 서비스 생성
1. [render.com](https://render.com) 접속 → GitHub 로그인
2. New → Web Service → GitHub 저장소 연결
3. 설정:
   - **Name**: 원하는 이름
   - **Root Directory**: `backend`
   - **Runtime**: Python
   - **Build Command**: `pip install -r requirements.txt`
   - **Start Command**: `uvicorn main:app --host 0.0.0.0 --port $PORT`

### 2-2. 환경변수 설정
Render 대시보드 → Environment 탭에서 아래 변수들을 추가한다:

| 키 | 값 |
|----|----|
| `DATABASE_URL` | Supabase Session pooler URL |
| `SECRET_KEY` | 랜덤 문자열 (예: `openssl rand -hex 32` 결과) |
| `GROQ_API_KEY` | Groq 콘솔에서 발급 |
| `GOOGLE_CLIENT_ID` | Google Cloud Console |
| `GOOGLE_CLIENT_SECRET` | Google Cloud Console |
| `GOOGLE_REDIRECT_URI` | `https://앱이름.onrender.com/auth/gmail/callback` |
| `FRONTEND_URL` | `https://앱이름.vercel.app` |
| `BACKEND_URL` | `https://앱이름.onrender.com` |

### 2-3. 배포 확인
Render 로그에서 아래 문장이 뜨면 성공:
```
Application startup complete.
```

> **Render 무료 티어 특징**
> 15분 동안 요청이 없으면 서버가 종료(sleep)된다.
> 다음 요청이 오면 재시작하는데 50초 이상 걸린다.
> 해결책: [UptimeRobot](https://uptimerobot.com)에서 5분마다 `/docs` 엔드포인트를 ping하도록 설정하면 sleep 방지 가능.

## 3단계 — Vercel (React 프론트엔드)

### 3-1. 프로젝트 생성
1. [vercel.com](https://vercel.com) 접속 → GitHub 로그인
2. Import Project → 저장소 선택
3. 설정:
   - **Root Directory**: `my-app`
   - **Framework Preset**: Vite (자동 감지됨)

### 3-2. 환경변수 설정
Vercel 프로젝트 Settings → Environment Variables:

| 키 | 값 |
|----|----|
| `VITE_API_BASE_URL` | `https://앱이름.onrender.com` |

### 3-3. SPA 라우팅 설정 (필수)
`my-app/vercel.json` 파일이 있어야 새로고침 시 404가 나지 않는다:
```json
{
  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
}
```

> **왜 필요한가?**
> React Router는 클라이언트 사이드 라우팅이다.
> `/documents` 같은 URL을 Vercel 서버에 직접 요청하면 해당 파일이 없어서 404가 뜬다.
> 모든 요청을 `index.html`로 돌려야 React가 라우팅을 처리할 수 있다.

### 3-4. 배포 확인
Vercel 대시보드에서 배포 완료 후 제공된 URL로 접속.

## Gmail OAuth 다른 사용자 연동 안 되는 문제

### 원인
Google Cloud Console OAuth 앱이 기본적으로 **"테스트(Testing)" 모드**로 생성된다.
테스트 모드에서는 직접 추가한 계정만 Gmail 연동이 가능하고, 나머지 사용자는 "이 앱은 확인되지 않았습니다" 오류가 뜬다.

### 해결 방법 A — 테스트 사용자 추가 (빠름, 최대 100명)
1. [console.cloud.google.com](https://console.cloud.google.com) 접속
2. 좌측 메뉴 APIs & Services → OAuth consent screen
3. "Test users" 섹션 → Add Users
4. 연동을 허용할 이메일 주소 추가 → Save

### 해결 방법 B — 앱 게시 (모든 사용자 허용)
1. APIs & Services → OAuth consent screen
2. "Publish App" 버튼 클릭
3. 확인 팝업에서 Confirm

> **주의**: Gmail의 `gmail.modify` 스코프는 민감 권한이다.
> 앱을 게시하면 Google 검증 심사를 요청할 수 있다는 안내가 뜨지만,
> 심사 없이도 게시는 된다. 단, 사용자가 "확인되지 않은 앱" 경고를 보고 직접 허용해야 한다.
> 정식 서비스라면 Google에 검증 신청을 해야 경고 없이 사용 가능하다.

### Redirect URI 등록 확인
1. APIs & Services → Credentials → OAuth 2.0 Client IDs 클릭
2. Authorized redirect URIs에 아래 항목이 있어야 한다:
   ```
   https://앱이름.onrender.com/auth/gmail/callback
   ```
3. 없으면 추가 후 Save

## 자주 발생하는 오류

### `No module named 'psycopg2'`
requirements.txt에 `psycopg2-binary` 누락. 추가 후 재배포.

### `DATABASE_URL is None`
Render 환경변수에 `DATABASE_URL`이 없거나 오타. Render → Environment 탭 확인.

### `Network is unreachable` (IPv6 오류)
Supabase 직접 연결 URL 사용 중. Session pooler URL로 교체.

### `password authentication failed`
- 비밀번호에 `!` 같은 특수문자 → URL 인코딩 필요 (`!` → `%21`), 또는 비밀번호를 특수문자 없이 재설정
- `.env`에 같은 키가 2개 있으면 첫 번째가 우선 적용됨 → 중복 삭제

### `ENUM type requires a name` (PostgreSQL)
SQLAlchemy에서 MySQL용 Enum은 이름이 없어도 되지만 PostgreSQL은 이름이 필수:
```python
# 잘못된 예 (MySQL에서만 동작)
Column(Enum('A', 'B'))

# 올바른 예 (PostgreSQL 호환)
Column(Enum('A', 'B', name='my_enum'))
```

### Vercel 배포 후 새로고침 시 404
`my-app/vercel.json` 파일 누락. 위 3-3 참고.

### CORS 오류
Render 환경변수 `FRONTEND_URL`이 Vercel 배포 URL과 다름.
`https://` 포함 여부, 끝에 `/` 유무까지 정확히 맞춰야 한다.
